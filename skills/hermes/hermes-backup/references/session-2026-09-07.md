# Session 2026-09-07 — SSH Remote Fails, Only HTTPS+PAT Works

## What Happened

1. `tar` from `~` succeeded → `hermes-backup-daily.tar.gz`
2. `git add && git commit` succeeded (local)
3. `git push origin main` failed with:
   ```
   fatal: could not read Username for 'https://github.com': No such device or address
   ```
4. Remote URL was already HTTPS: `https://github.com/ClawTwice/hermes-backup.git`
   - No embedded token → password prompt fails silently with no user present
5. Tried switching remote to SSH: `git@github.com:ClawTwice/hermes-backup.git`
   - `ssh -o ConnectTimeout=10 git@github.com` → **Connection timed out during banner exchange**
   - Port 22 is blocked; SSH remote is completely non-functional on Termux
6. No `$GITHUB_TOKEN` env var set; no `~/.netrc`; no `gh auth`; no `~/.git-credentials`

## Confirmed Truth

| Method | Status on Termux |
|--------|-----------------|
| HTTPS remote + embedded PAT (`https://$TOKEN@github.com/...`) | ✅ Works |
| HTTPS remote, no token | ❌ "could not read Username" |
| SSH remote (`git@github.com:...`) | ❌ Port 22 blocked, connection timeout |

**The ONLY working push path on Termux is HTTPS with PAT embedded in the URL.**

## Required Fix (Not Yet Applied)

```bash
# Set GITHUB_TOKEN env var first
export GITHUB_TOKEN="ghp_YOUR_TOKEN_HERE"

# Embed in remote URL

# Push
git push origin main
```

Or set `GITHUB_TOKEN` persistently in `~/.bashrc`.
