# Backup Session 2026-09-03 — Root Cause: Repo-level socks5 Proxy Override

## What happened

Git push silently hung for 60+ seconds, then died with:
```
fatal: could not read Username for 'https://github.com': terminal prompts disabled
```

## Investigation sequence

1. **Cleared global proxy** (`git config --global --unset http.proxy`) → still hung
2. **Examined `.git/config` directly** → found the real culprit:

```ini
[http]
    proxy = socks5h://172.19.0.1:7890
[https]
    proxy = socks5h://172.19.0.1:7890
```

3. **Repo-level config overrides global** — even after unsetting global, the repo-level socks5 entry was still active
4. **Killed hung git process**, unset at repo level, push immediately succeeded

## Key lesson

`git config --list` may not show the effective proxy if there's a repo-level override.
Always read `.git/config` directly:
```bash
git -C ~/hermes-backup-git cat .git/config
```

Look for any `[http]` / `[https]` sections with `proxy = socks5h://...` — this is the real config git is using.

## Fixed push

```bash
git -C ~/hermes-backup-git config --unset http.proxy
git -C ~/hermes-backup-git config --unset https.proxy
git -C ~/hermes-backup-git GIT_TERMINAL_PROMPT=0 git push origin main
# → Exited with code 0, push succeeded
```

## Also found: No GitHub credentials configured

```
error: unknown option `timeout=30'
...
gh auth status → "You are not logged into any GitHub hosts"
~/.netrc → empty
~/.hermes/github_token → does not exist
```

Git push succeeded anyway because `GIT_TERMINAL_PROMPT=0` suppresses the password prompt — but the commit `3592b48` was pushed with no auth, meaning the remote was already set up with an embedded token in a previous successful push. If the embedded token ever rotates, push will fail with the "could not read Username" error again.
