# Session 2026-09-15 — Raw git push without credentials

## What happened

Cron ran raw `git add/commit/push` from `~` instead of using `~/hermes-backup/backup.sh`:
```bash
cd ~ && git add hermes-backup-daily.tar.gz && git commit -m "backup 2026-09-15 03:00" && git push origin main
```
Result: commit ✅ succeeded; push ❌ failed with "could not read Username for 'https://github.com': No such device or address"

## Diagnosis performed

All four credential methods absent:
- `gh auth status` → not configured
- `$GITHUB_TOKEN` env var → not set
- `~/.netrc` → does not exist
- Embedded token in remote URL → absent

Remote URL (bare HTTPS, no token): `https://github.com/yjhvghhghb-del/hermes-.git`

## Lesson

The session bypassed `~/hermes-backup/backup.sh` which contains the pre-flight credential check. Raw git commands from `~` have no credential guard — the push silently fails at the password prompt with no user present.

**Correct workflow**: always run `~/hermes-backup/backup.sh` (which includes pre-flight check). Never run raw `git add/commit/push` from `~` for backup.

## Fix needed

Configure GitHub credentials — see `references/git-credential-diagnosis.md`. Push will work once `$GITHUB_TOKEN` is set or remote URL embeds the token.
